# `strong_gap_up_v1` 短线化调整任务与验收

> 依据：[短线化策略调整计划](short_gap_adjustment_plan.md)
>
> 本文只规定策略行为、交付顺序和验收证据，不规定类、函数或文件组织。开发 Agent 不得重新设计策略，不得在未裁决项上自行增加指标或宣称参数最优。
>
> 当前状态：`implemented=yes, fixture_verified=yes, api_verified=yes, pit_backtest_verified=no`。SG-05最终阶段切分和PIT参数裁决仍未完成。

## 1. 交付原则

- 这是现有策略的版本化调整，不创建第二套独立策略。
- 旧版本的配置、信号和回测结果必须可追溯，不能被新口径覆盖。
- 每项验证分为 `implemented`、`fixture_verified`、`api_verified`、`pit_backtest_verified`；没有真实 PIT 证据时最后一项必须为否。
- 先完成行为和可观测数据，再做 PIT 参数裁决；不在本轮执行自动参数寻优。
- 实际服务验收必须启动 FastAPI 并通过 HTTP 调用，不以单元测试代替 API 链路。

## 2. 工作包与顺序

### SG-01：版本与数据契约

目标：新旧策略结果可以并存和追溯，前端能够区分 SHORT_GAP、STRICT_GAP、D1 承接状态和交易有效期。

必须交付：

- 新策略版本及完整配置快照、配置哈希。
- 原始 `gap_floor`、`gap_top` 在 D0 后保持冻结的审计字段。
- SHORT_GAP/STRICT_GAP 标签、D1 承接类型、部分回补风险、缺口阶段和评分分量。
- 明确区分“获得交易资格”和“实际持仓”；推荐数据不得声称用户已买入。
- 历史旧版本查询和回测结果保持不变。

验收：同一股票同一 D0 可分别追溯旧版 D3 口径与新版 D1 口径；重复运行幂等；新旧配置不会写入同一自然唯一记录。

### SG-02：D0 候选分层

目标：保留真正向上缺口、放量、强势收盘和突破，同时把趋势成熟度从一票否决改成质量评价。

必须交付：

- SHORT_GAP V0 候选入口：0.5% 缺口、1.5 倍量比及计划中其余结构性硬条件。
- STRICT_GAP 子集标签：1% 缺口、2倍量比及原严格趋势/平台条件。
- 前置涨幅、平台振幅、平台漂移失败时，SHORT_GAP 不得仅因此被删除；实际值仍进入评分和风险解释。
- 每个硬条件继续输出实际值、比较符和阈值；每个标签说明命中原因。
- D0 检测严格截断到 D0，量比历史窗口不包含 D0。

边界验收：

- `low == D-1.high` 不是候选；略高于前高且 gap 恰好 0.5% 可进入 SHORT_GAP。
- gap 0.49% 失败；量比 1.49 失败；边界 1.5 通过。
- gap 0.8%、量比 1.8、前置涨幅 8% 可以是 SHORT_GAP，但不能是 STRICT_GAP。
- gap 1%、量比 2且严格形态全部满足时，同时具有两个标签。
- 阴线、弱收盘、未突破、停牌或数据不足仍失败。

### SG-03：D1 承接与交易资格

目标：D1 收盘完成第一轮确认，D2 获得最早交易资格。

必须交付：

- D1 完整回补、部分回补后收回、部分回补未收回、完全未回补、数据不确定五类互斥结果。
- 完整回补永久失效；完全未回补获得 D2 资格。
- 部分回补且 `D1.close >= gap_top` 的 V0 规则获得 D2 资格并携带风险；未收回者不进入默认 D2 候选。
- D1 停牌、缺失或无效数据不能被当成未回补。
- 确认日期为 D1，最早交易日期由交易日历推导为 D2。
- D2、D3 更新的是交易后验证轨迹，不得重新成为默认入场前置条件。

边界验收：`D1.low == gap_floor` 失效；`D1.low == gap_top` 为完全未回补；跨周末和长假正确推导 D1/D2；重复推进不倒退、不重复追加状态。

### SG-04：D0 + D1 可解释排序

目标：排序面向未来 1～3 日短线表现，并提高 D1 承接信息的重要性。

必须交付：

- 分开输出 D0 启动质量与 D1 承接质量。
- D0 至少覆盖缺口、量比、收盘强度、突破、前置趋势、平台质量和缺口阶段。
- D1 至少覆盖缺口保留比例、部分回补及收回、收盘强度、价格稳定性和成交状态。
- 总分只在通过硬门槛和 D1 裁决的候选间排序，不命名为概率或置信度。
- 权重、裁剪上限和原始值进入版本化配置；同一输入结果稳定。

验收：降低前置涨幅不会单独删除候选但会影响质量；更强 D1 承接在其他条件相同时得到更好的 D1 分量；任何高分都不能让完整回补信号恢复资格。

### SG-05：同一上涨阶段的缺口序列

目标：保留第1/第2/第3+缺口风险，同时停止把“固定前20日计数”等同于上涨阶段。

必须先提交策略裁决证据：

- 只用 D0 当时可见数据的阶段开始、持续和重置规则。
- 第一个、第二个、第三个有效未补缺口的确定性样例。
- 旧缺口跨越固定20日边界、缺口完整回补后重置、阶段结束后重新启动的样例。
- 规则不得依赖未来回撤、未来最高价或新增指标体系。

完成裁决后才能实现。裁决前允许保留旧 V0 标签用于开发对照，但 API 和报告必须明确其仍是固定窗口近似，不得冒充最终阶段定义。

### SG-06：D2 入场与短线退出回测

目标：无前视地验证 D0 跳空、D1 承接后未来 1～3 日是否存在成本后优势。

必须交付：

- D1 收盘后才形成可用信号，最早 D2 成交。
- D2 停牌或一字涨停不得虚构成交。
- “只允许 D2 入场”和“允许延迟至 D3”必须作为两个独立方案，不混合样本。
- 固定期限分别计算实际入场后 1、2、3、4、5 个交易日，不再用 10 日代表短线目标。
- 4日与5日强制时间退出分开统计，任何事件不得持有超过所选上限。
- 入场后原始缺口完整回补触发核心失效；退出价格必须遵守日线信息可用时间和 T+1。
- 每个事件保存状态路径、实际成交日、不可成交原因、退出原因、费用和数据质量。

指标验收：毛/净收益、样本数、均值、中位数、胜率、P10/P90、MFE、MAE、完整回补率及首次回补日全部可追溯到单事件。

分组验收：SHORT/STRICT、D1完全未回补/部分回补后收回、缺口序号、D2/D3入场、4/5日退出均有独立样本数和指标，不能只给总体均值。

### SG-07：扫描与 API 行为

目标：前端看到的是 D1 后可参与的短线候选和清晰的有效交易日，而不是旧版 D3 确认结果。

必须交付：

- 扫描按交易日历补齐足以发现 D0 并完成 D1 裁决的日期，不用自然周代替交易日。
- 默认推荐返回 D1 已确认、处于允许交易窗口、且非 `exhaustion_risk` 的候选。
- 可显式查询 D0 待确认、D1 弱承接、完整回补、不确定、过期及衰竭风险记录。
- 响应包含 D0、D1、最早交易日、候选标签、承接类型、原始缺口边界、失效状态、评分分量及数据新鲜度。
- 空结果、旧数据、上游失败继续保持可区分。

HTTP 验收至少覆盖：默认候选、显式风险候选、单股票历史、非交易日错误、陈旧数据和真实空结果。默认接口不得继续以“D3 confirmed”作为唯一入口。

### SG-08：真实数据与文档验收

目标：把实现证据与参数有效性证据严格分开。

必须交付：

- Ruff、完整测试、编译检查结果。
- 使用 FastAPI 实际启动和 HTTP 调用验证完整代码链路。
- 使用当前数据执行 SHORT_GAP 与 STRICT_GAP 扫描，报告各阶段数量及被每个硬条件排除的数量。
- 使用 PIT 沪深300成分和 PIT 证券状态完成参数裁决回测；缺少 PIT 时明确标为未完成，不能用当前成分快照替代。
- README、API 文档和验证报告更新策略时钟、字段、命令、风险与版本迁移说明。

## 3. 待 PIT 回测裁决项

以下内容不得由开发 Agent 凭感觉确定最终默认值：

| 裁决项 | 必须比较的方案 | 发布证据 |
|---|---|---|
| SHORT_GAP 入口 | 0.5%/1.5倍 V0 与 1%/2倍严格基线，必要时只做少量预注册离散方案 | 分年度、成本后、样本量与稳定性 |
| 部分回补资格 | 收盘重回 `gap_top` 的 V0 与更弱/更强预注册方案 | 未来1～3日净收益、MAE、回补率 |
| 延迟入场 | 仅D2与允许D3 | 成交率、净收益、追高风险 |
| 最大持有 | 4日与5日 | 收益集中区间、MFE/MAE、回补率 |
| D0/D1评分权重 | 少量预注册权重版本 | 排序分层的样本外单调性，不做全量寻优 |
| 上涨阶段切分 | 经人工裁决的因果结构规则 | fixture一致性与PIT分组有效性 |

任何比较都必须保留全样本和样本外区间，不得只展示表现最好的一组。

## 4. 禁止项审计

开发完成时必须确认：

- 没有新增独立策略来绕开版本迁移。
- 没有加入机器学习、MACD、KDJ、RSI或无关指标。
- 没有取消真实向上缺口、放量、强势收盘、突破和D1承接。
- 没有为了候选数量自动降低阈值。
- 没有使用未来数据划分趋势阶段、确认D1或生成D2成交。
- 没有把规则分称为概率、置信度或胜率。
- 没有把当前 CSI300 快照回测称为 PIT 正式验证。

## 5. 完成定义

只有同时满足以下条件，本轮才能标记完成：

1. D0→D1→D2 的策略时钟已替代默认 D3→D4 时钟，旧版本仍可追溯。
2. SHORT_GAP 与 STRICT_GAP 分层、D1 五类裁决及 D0+D1 评分均通过边界测试。
3. API 通过真实 HTTP 调用返回 D1 后候选及完整解释，空结果和故障语义正确。
4. 回测严格遵守 PIT、无前视、可成交性、费用和 T+1，并提供1～5日及所需分组指标。
5. 4/5日时间退出、D2/D3入场及V0阈值已经过预注册方案比较。
6. 同一上涨阶段的缺口计数规则已单独裁决和验证；若未完成，不能把相应风险标签标记为正式有效。
7. 验证报告分别列出实现状态、fixture状态、API状态和PIT回测状态，不以其中一项代替另一项。

在 PIT 数据缺失时，可以完成开发与 API 验证，但整体状态只能是 `implemented=yes, fixture_verified=yes, api_verified=yes, pit_backtest_verified=no`，不得发布“阈值有效”结论。
